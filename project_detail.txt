1. INTRODUCTION

1.1 Document Purpose
-------------------
This document provides a comprehensive specification for the LocalB2B platform, 
a B2B marketplace that connects local sellers and retailers. It outlines the 
system architecture, functional requirements, technical specifications, and 
implementation details for stakeholders including developers, project managers, 
and business analysts.

The document serves as the primary reference for understanding the complete 
workflow, technology stack, database structure, and feature specifications 
of the LocalB2B platform.

1.2 Product Scope
-----------------
LocalB2B is a comprehensive B2B marketplace platform designed to facilitate 
business-to-business transactions between local sellers and retailers. The 
platform provides:

• Multi-role user management (Sellers, Retailers, Admins)
• Product catalog management with image support
• Order placement and tracking system
• Real-time SMS notifications via Twilio integration
• Automated PDF invoice generation
• Analytics and reporting dashboards
• Location-based supplier discovery
• Secure authentication and authorization

The platform aims to digitize local B2B commerce, reduce transaction friction, 
and provide transparency in the supply chain for small to medium businesses.

2. OVERALL DESCRIPTION

2.1 Product Overview
-------------------
LocalB2B is a modern, full-stack web application that serves as a digital 
marketplace for B2B transactions. The platform bridges the gap between local 
suppliers and retailers by providing a centralized platform for product 
discovery, ordering, and transaction management.

### System Architecture
The application follows a client-server architecture with clear separation 
of concerns:

**Frontend (Client)**
• Technology: React 18 with Vite build system
• Routing: React Router DOM for navigation
• State Management: TanStack Query for server state
• Styling: Tailwind CSS for responsive design
• Forms: React Hook Form with Zod validation
• Charts: Chart.js for analytics visualization

**Backend (Server)**
• Technology: Express.js with Node.js runtime
• Database: MySQL with Sequelize ORM
• Authentication: JWT-based token system
• File Upload: Multer for image handling
• SMS Service: Twilio integration
• PDF Generation: PDFKit for invoice creation

**Database Structure**
• Users: Account management and role-based access
• Products: Catalog management with image support
• Orders: Transaction tracking and status management
• OrderTimeline: Audit trail for order status changes

### Key Components
1. **Authentication System**: Secure login/registration with role-based access
2. **Product Management**: CRUD operations for product catalog
3. **Order Processing**: End-to-end order lifecycle management
4. **Notification System**: Real-time SMS alerts for order updates
5. **Invoice Generation**: Automated PDF creation and download
6. **Analytics Dashboard**: Business intelligence and reporting
7. **Admin Panel**: Platform management and user oversight

### User Roles and Permissions
**Sellers**
• Create and manage product listings
• View and process incoming orders
• Update order status and generate invoices
• Access sales analytics and reports

**Retailers**
• Browse and search product catalog
• Place orders with MOQ validation
• Track order status and download invoices
• Manage account and business information

**Admins**
• Oversee platform operations
• Manage user accounts and permissions
• Monitor system analytics and performance
• Handle platform configuration and settings

3.3 Use Case Model
------------------

### UC-1: User Registration and Login
**Actors:** Seller, Retailer
**Preconditions:** User has internet access and valid email
**Main Flow:**
1. User navigates to registration page
2. User selects role (Seller/Retailer)
3. User fills registration form with business details
4. System validates input and creates account
5. User receives confirmation and can login
6. System generates JWT token for session management

**Alternative Flows:**
• Email already exists: System displays error message
• Invalid input: System highlights validation errors
• Registration failure: System displays appropriate error message

### UC-2: Product Listing Creation
**Actors:** Seller
**Preconditions:** Seller is logged in and account is active
**Main Flow:**
1. Seller navigates to product management section
2. Seller clicks "Add New Product" button
3. Seller fills product information form
4. Seller uploads product images (up to 5)
5. Seller sets pricing and MOQ information
6. System validates and saves product listing
7. Product becomes available in marketplace

**Alternative Flows:**
• Image upload failure: System displays error and allows retry
• Invalid MOQ: System validates minimum quantity requirements
• Missing required fields: System highlights incomplete information

### UC-3: Order Placement
**Actors:** Retailer
**Preconditions:** Retailer is logged in and product is available
**Main Flow:**
1. Retailer browses product catalog
2. Retailer selects desired product
3. Retailer specifies quantity (must meet MOQ)
4. Retailer reviews order details
5. Retailer confirms order placement
6. System creates order record and notifies seller
7. Order appears in both parties' dashboards

**Alternative Flows:**
• Quantity below MOQ: System displays error and minimum requirement
• Product unavailable: System displays out-of-stock message
• Order creation failure: System displays error and suggests retry

### UC-4: Order Status Management
**Actors:** Seller
**Preconditions:** Order exists and seller has permission to update
**Main Flow:**
1. Seller views pending orders in dashboard
2. Seller selects order to update
3. Seller changes status to next stage
4. System updates order timeline
5. System generates invoice if status is "Shipped"
6. System sends SMS notification to retailer
7. Updated status reflects in both dashboards

**Alternative Flows:**
• SMS delivery failure: System logs error but continues process
• Invoice generation failure: System displays error message
• Invalid status transition: System prevents unauthorized changes

### UC-5: Invoice Download
**Actors:** Seller, Retailer
**Preconditions:** Order has been shipped and invoice generated
**Main Flow:**
1. User navigates to order details page
2. User clicks "Download Invoice" button
3. System retrieves PDF invoice from storage
4. System initiates file download to user's device
5. Invoice opens in PDF viewer or downloads to device

**Alternative Flows:**
• Invoice not found: System displays error message
• Download failure: System suggests retry or contact support
• PDF viewer unavailable: System forces download instead

### UC-6: Product Search and Filtering
**Actors:** Retailer
**Preconditions:** User has access to product catalog
**Main Flow:**
1. Retailer navigates to product catalog
2. Retailer enters search terms or applies filters
3. System processes search query and filters
4. System displays matching products with pagination
5. Retailer can further refine search or view products
6. Search results update dynamically with filter changes

**Alternative Flows:**
• No results found: System displays "no products found" message
• Search timeout: System displays error and suggests retry
• Filter combination invalid: System resets to default view

### UC-7: Analytics Dashboard Access
**Actors:** Seller, Admin
**Preconditions:** User has appropriate role and permissions
**Main Flow:**
1. User navigates to analytics/dashboard section
2. System loads relevant charts and statistics
3. User can select date ranges and filter options
4. Charts update dynamically based on selections
5. User can export data or generate reports
6. System provides drill-down capabilities for detailed analysis

**Alternative Flows:**
• Data loading failure: System displays error and refresh option
• No data available: System displays empty state with guidance
• Export failure: System displays error and suggests alternative formats

### UC-8: Administrative User Management
**Actors:** Admin
**Preconditions:** Admin is logged in with appropriate permissions
**Main Flow:**
1. Admin navigates to user management section
2. Admin views list of all platform users
3. Admin can search and filter users by various criteria
4. Admin selects user to modify
5. Admin updates user status or permissions
6. System applies changes and logs administrative action
7. Affected user receives notification of status change

**Alternative Flows:**
• User not found: System displays search results with suggestions
• Permission denied: System displays authorization error
• Update failure: System displays error and suggests retry

TROUBLESHOOTING GUIDE
====================

Common Issues and Solutions:

1. Images Not Displaying:
   - Check uploads directory exists: server/uploads/
   - Verify image URLs in database: SELECT images FROM products;
   - Confirm static file serving: app.use('/uploads', express.static(uploadsDir));
   - Test direct URL: http://localhost:5000/uploads/eco-bag-sample.svg

2. Database Connection Issues:
   - Verify .env file has correct MYSQL_DB=local_b2b_2
   - Check MySQL service is running
   - Confirm user permissions for database access
   - Run: node test-db.js to verify connection

3. API 500 Errors:
   - Check server console for detailed error messages
   - Verify Sequelize model associations are correct
   - Test individual endpoints with Postman/curl
   - Review orderController.js for SQL query issues

4. Authentication Problems:
   - Clear browser localStorage and cookies
   - Verify JWT_SECRET is set in .env file
   - Check token expiration and refresh logic
   - Test with fresh user registration

5. File Upload Failures:
   - Verify multer configuration in upload routes
   - Check file size limits and allowed types
   - Ensure uploads directory has write permissions
   - Test with different image formats (JPEG, PNG, SVG)
